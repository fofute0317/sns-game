# ゲームバランスの検証と、発注仕様からの変更点

> ## 📌 通貨について（2026-08-15 変更）
>
> ゲーム内のお金の単位を **ポイント（pt）から円** に変更しました。
> 初期資金は **10,000,000円（1,000万円）** です。
>
> **すべての金額を1万倍しただけ**なので、比率は一切変わっておらず、
> **このドキュメントのバランス検証結果はそのまま有効**です。
>
> 以下の本文に出てくる数値は、**「pt」を「万円」に読み替えてください。**
> （例: 初期資金 1,000pt → 1,000万円 ／ カカオ 100pt → 100万円）
>
> 画面表示も万円にそろえています。円そのまま（`10,000,000円`）で出したい場合は、
> `config/rules.mvp.json` の `game.currency` を
> `{ "unit": 1, "unitLabel": "円" }` に変えてください。


このドキュメントは、2026-08-10 にご提示いただいた計算ルールを実装するにあたって

- **そのまま実装すると何が起きるか**
- **どこを、なぜ変えたか**
- **変えた結果、本当にバランスが取れているか**

を、実際に数千回対戦させた結果とあわせて説明するものです。

ご指定の数値は `config/rules.spec.json`（発注仕様どおり・未調整）としてそのまま残してあり、
先生用コンソールの「ルールセット」から選んで比較プレイできます。

## 1. まず結論

いただいた数値をそのまま使うと、**「一般市場の原料を買って高く売る」が圧倒的に有利**になり、
ご要望であった

> フェアトレードを選択すれば必ず勝つ、という仕組みにはしたくありません（＝どの戦略にも勝ち筋がほしい）

の**逆側の問題**（フェアトレードを選ぶ意味がまったく無い）が発生します。

そこで、**ご指定の主要な数字（初期資金1,000／5ラウンド／カカオ100・120・140／販売価格200・250・300／
広告0・50・100／還元0・30・60／総合得点60:25:15）はすべて維持したまま**、
それ以外のパラメータを調整して、どの戦略にも勝ち筋がある状態にしました。

調整後の対戦結果（8戦略・5人対戦・1,500ゲーム）:

| 戦略 | 総合1位率 | 利益1位率 | 平均最終資金 |
|---|---:|---:|---:|
| 全部認証・高価格（高級路線） | 30.2% | 7.8% | 3,056 |
| 薄利多売（一般市場・安価格・広告最大） | 28.9% | 31.7% | 2,950 |
| 全部認証・高価格・還元最大 | 22.6% | 1.5% | 2,900 |
| カカオだけ認証・高価格 | 19.3% | 22.4% | 3,095 |
| 直接取引・高価格 | 19.1% | 22.9% | 3,218 |
| 徹底コスト削減（一般市場・高価格） | 18.9% | 45.1% | 3,348 |
| 無難な経営（一般市場・標準価格） | 18.6% | 26.1% | 3,232 |
| 一般市場だが還元は最大 | 2.5% | 2.4% | 3,039 |

5人対戦なので、完全に公平なら各戦略は 20% 前後になります。
最後の1つを除き **18.6%〜30.2% に収まっており、支配的な戦略も死んだ戦略もありません**。

> **「一般市場だが還元は最大」だけが弱いのは意図的です。**
> 「安く買い叩いたうえで、その一部を寄付で返す」は、
> 「はじめから公正な価格で買う」より効果が薄い、という教材上のメッセージになります。
> 授業のふりかえりで使える論点なので、あえて弱いまま残しています。

再現方法:

```bash
node tools/simulate.js --games 2000        # 調整後
node tools/simulate.js --rules spec        # 発注仕様どおりの数値で同じ検証
```

## 2. 発注仕様のまま実装すると起きること

### 2-1. 「安く売る」が数学的に必ず損になる

ご指定の値は次のとおりでした。

- 販売価格: 安い200 / 標準250 / 高い300
- 販売数量: 価格が安い +20% / 標準 ±0% / 高い −20%

1個あたりの利益（＝販売価格 − 原料費）を仮に原料費 200 とすると、

| 価格 | 1個の利益 | 販売数(基準100) | もうけ |
|---|---:|---:|---:|
| 安い 200 | 0 | 120 | **0** |
| 標準 250 | 50 | 100 | 5,000 |
| 高い 300 | 100 | 80 | **8,000** |

価格を 25% 上げても販売数は 16.7% しか減らないため（＝価格弾力性が1未満）、
**値上げすれば必ずもうかる**という構造になっています。
つまり「販売価格」は選択肢が3つあるように見えて、実質的に答えが1つに決まってしまいます。

### 2-2. 原料費が販売価格に対して高すぎ、認証原料がほぼ選べない

カカオも砂糖も 100 / 120 / 140 とすると、1個あたりの原料費は 200〜280 です。
販売価格が 200〜300 なので、

| 原料 | 原料費 | 安い(200) | 標準(250) | 高い(300) |
|---|---:|---:|---:|---:|
| 両方とも一般市場 | 200 | ±0 | +50 | +100 |
| 両方とも直接取引 | 240 | **−40** | +10 | +60 |
| 両方とも認証 | 280 | **−80** | **−30** | +20 |

認証原料を選ぶと、高価格で売っても1個あたり 20 しか残りません（一般市場の 1/5）。
**認証を選んだ時点でほぼ経営が成立しない**状態です。

### 2-3. 広告費・還元額が、桁として小さすぎる

基準販売数量 100個 × 販売価格 250 = 売上 25,000 に対して、
広告費 50〜100、還元 30〜60 は **売上の 0.2〜0.4%** です。
初期資金 1,000 も、1ラウンドの利益（数千）に対して意味を持ちません。

これらは「選択肢が存在するのに、結果に影響しない」状態になります。

### 2-4. 実際に対戦させた結果

`node tools/simulate.js --rules spec` を実行すると、
「一般市場・高価格」が利益で圧勝し、認証系の戦略はほぼ勝てないことが数字で出ます。

## 3. 変更した点と、その理由

### ✅ 変更していないもの（ご指定のまま）

初期資金 1,000 pt / 5ラウンド / カカオ 100・120・140 /
販売価格 200・250・300 / 広告費 0・50・100 / 追加還元 0・30・60 /
総合得点の比率 利益60% : 生産者25% : 社会環境15% /
利益ランキング → 総合ランキングの2段階発表 / 4〜6人 / 5種類のイベント

### 変更 1: 販売数量の基準を「100個」から「5ロット（＝5,000個）」へ

**理由**: 2-3 のとおり、基準100個のままだと広告費と還元額が誤差になってしまうためです。

数量の単位を「ロット（1ロット＝1,000個）」とし、基準を 5 ロットにしました。
仕入価格・販売価格は 1ロットあたりの金額です。
これにより、

- 広告100pt … 1ロットの利益が 100〜160 なので、**販売数が1ロット増えれば元が取れる**
- 還元60pt … 1ラウンドの利益の約 10%。**痛いが致命的ではない**
- 初期資金1,000pt … 1ラウンドの利益の約2倍。**赤字が続けば効いてくる**

と、すべての選択肢が意味を持つようになりました。

### 変更 2: 砂糖の価格を 100/120/140 → 40/50/60 に

**理由**: 2-2 のとおり、カカオと砂糖の両方が同額だと原料費が販売価格に迫り、
どの組み合わせでも利益がほとんど出ないためです。

**教材としても、こちらのほうが正確です。** 実際の国際相場でも、
カカオ豆は砂糖より1トンあたり10倍前後高価です。
なお **認証原料の割増率（＋40%）はカカオと同じ**に揃えてあります。

### 変更 3: 価格による販売数の変化を ±20% → 安い +85% / 高い −25% に

**理由**: 2-1 のとおり、±20% では値上げが常に正解になってしまうためです。

1個あたりの利益が 60（安い）／110（標準）／160（高い）なので、
3つの価格が互角になるには、安い価格の販売数がおよそ 1.8 倍必要という計算になります。

調整後は次のようになります（原料が一般市場の場合の1ラウンドの利益）:

| 価格 | 販売数 | 1ロットの利益 | もうけ |
|---|---:|---:|---:|
| 安い 200 | 9.25 | 60 | 555 |
| 標準 250 | 5.0 | 110 | 550 |
| 高い 300 | 3.75 | 160 | 600 |

**3つとも互角**になりました。一方、認証原料（原料費200）の場合は、

| 価格 | 1ロットの利益 | もうけ |
|---|---:|---:|
| 安い 200 | 0 | 0 |
| 標準 250 | 50 | 約310 |
| 高い 300 | 100 | 約400 |

となり、**高い原料を使うなら高く売らないと成立しない**という関係が生まれます。
これは「良いものを適正な価格で売る」という、教材として伝えたい構造そのものです。

### 変更 4: 「社会貢献ポイント」を「生産者への貢献」と「社会・環境への貢献」に分けた

**理由**: 総合得点を「利益60% : 生産者25% : 社会環境15%」で計算するには、
生産者への貢献と社会・環境への貢献が別々の数値である必要があるためです。
ご提示の仕様では1つの「社会貢献ポイント」にまとまっていました。

| 原料 | 生産者への貢献 | 社会・環境への貢献 | 考え方 |
|---|---:|---:|---|
| 一般市場 | 0 | 0 | 誰にいくら届いたか分からない |
| 直接取引 | 10 | 3 | 生産者には多く払うが、環境や労働の基準・監査は無い |
| 国際フェアトレード認証 | 20 | 12 | 最低価格＋プレミアムに加え、環境基準・児童労働の禁止・第三者監査がある |

追加還元は 30pt → 生産者8・社会5、60pt → 生産者16・社会10 としました。

### 変更 5: 市場イベントの効果を強くした

| イベント | 発注仕様 | 調整後 |
|---|---|---|
| カカオ不作 | 一般市場カカオ +40% | 一般市場 **+100%**、直接取引 +35%、認証 変化なし |
| 砂糖の高騰 | 一般市場砂糖 +30% | 一般市場 **+75%**、直接取引 +25%、認証 変化なし |
| フェアトレードへの関心上昇 | 認証使用商品 +20% | **+50%** |
| 節約志向 | 高価格商品 −20% | **−50%** |
| SNSで話題 | 広告100ptの会社 +20% | **+50%** |

**理由その1（ゲーム性）**: 効果が小さいと、5ラウンドを通して「最初に選んだ戦略」がそのまま勝ち、
毎年の判断が結果を変えません。シミュレーションでも、弱いイベントでは
特定の戦略が 80〜90% 勝つ状態になりました。イベントを強くしたことで、
**その年のニュースを見て手を変えることが意味を持つ**ようになりました。

**理由その2（現実との整合）**: 2024年には、実際にカカオの国際価格が約3倍に高騰しています。
+100% はむしろ控えめな数字です。

**理由その3（教材の核心）**: 直接取引に「部分的な保護」を持たせたことが重要です。

- 一般市場 … 相場の直撃を受ける（+100%）
- 直接取引 … 契約があるので影響は小さい（+35%）
- 認証 …… **フェアトレード最低価格の仕組みがあるので変わらない（±0）**

「フェアトレードと言っているだけの取引」と「国際フェアトレード認証」の違いを、
**説明ではなくゲームの結果として体験できます**。ここが今回いちばん大事にした部分です。

### 変更 6: 認証原料に小さな常時需要ボーナスを付けた（+6%、直接取引は +4%）

**理由**: 認証マークのある商品を選ぶ消費者は、イベントが起きていない年にも一定数います。
大きくすると「認証を選べば勝つ」ゲームになってしまうため、**あえて小さく**しています。
認証が大きく有利になるのは、あくまで「消費者の関心が高まった年」だけです。

### 変更 7: 1ラウンド目は必ず「おだやかな1年」にした

**理由**: 1年目でルールを理解してもらうためです。
いきなり価格高騰が起きると、ルールの理解と異常事態の対応が同時に来てしまいます。

### 変更 8: イベントは「ラウンド開始時」に発表する

**理由**: 決定後に発表すると運任せのゲームになりますが、
決定前に発表すると「今年はカカオが高い。どうする？」という**判断と会話**が生まれます。
教室での話し合いを起こすことが目的なので、開始時発表にしました。

### 変更 9: 選択の運の幅を ±5〜10% → ±10% に

ご指定の範囲内です。同じ選択でも毎回まったく同じ結果にはなりません。

## 4. 数値の調整方法（納品後もご自身で変えられます）

すべての数値は `config/rules.mvp.json` にあります。プログラムの変更は不要です。

```jsonc
// 例: フェアトレード認証カカオを 140 → 150 にする
{ "id": "fairtrade", "unitCost": 150, "producer": 20, "society": 12 }
```

変更したら、壊れていないかを確認できます。

```bash
npm test                    # ルールの整合性と、ゲームが最後まで成立するかを確認
node tools/simulate.js      # 2,000ゲーム対戦させて、支配的な戦略がないかを確認
```

さらに、**良い数値の組み合わせを自動で探すツール**も用意しています。

```bash
node tools/tune.js              # 数百通りを試して、バランスの良い組み合わせを表示
node tools/tune.js --apply      # いちばん良かった値を config に書き戻す
```

授業で実際にプレイして「ここが強すぎる／弱すぎる」と分かったときは、
`config` の数値を変えて `node tools/simulate.js` を回す、という手順で確認できます。

## 5. 「競争モード」について（任意）

先生用コンソールのルーム作成画面で、市場のモデルを選べます。

- **通常モード（既定）** … 各社がそれぞれのお客さんに売る。ご提示の計算式どおり。
- **競争モード** … クラス全体のお客さんを各社で奪い合う。他社より安く・目立つほど自社が売れる。

競争モードのほうが「対戦している」感覚は強くなりますが、
自分の結果が他人の選択に左右されるため、中学生には説明が少し難しくなります。
**まず通常モードで試し、物足りなければ競争モードを試す**ことをおすすめします。

```bash
node tools/simulate.js --mode share    # 競争モードでのバランス確認
```

## 6. 今後の検証ポイント（実際に生徒がプレイしたあとで）

シミュレーションで分かるのは数値のバランスだけです。次は実際のプレイで確認したいところです。

1. 1ラウンドに何分かかるか（5ラウンド＋結果発表で20〜30分に収まるか）
2. 5つの決定項目は中学生にとって多すぎないか（多ければ `enabled: false` で減らせます）
3. 「ロット」という単位が理解の妨げにならないか
4. イベントの文章が長すぎないか
5. 総合ランキングで順位が入れ替わったとき、生徒が納得できるか

いずれも `config` の変更だけで対応できるよう作ってあります。

# 追補: 発注者の追加要望による改訂（1パレット制・初期資金300万円・リサーチ加点）

面談と追加指示にもとづき、次の3点を反映しました。

## 1. ゲームの条件を「カカオ豆1パレット＋砂糖1パレット」にした

1ラウンド＝1バッチ（カカオ豆1パレット 約700kg ＋ 砂糖1パレット 約1t ＝ 板チョコ約30,000枚）です。

調達方法は発注者の指定どおり、輸入・国内調達・チョコレート原料の輸入から選べます。

| 決定 | 選択肢 | 1バッチあたり | 根拠 |
| --- | --- | ---: | --- |
| カカオ | チョコレート原料を輸入 | 78万円 | 加工済み原料。安いが産地をたどれない |
| | 国内商社の一般カカオ豆 | 85万円 | 基準 |
| | 生産者と直接取引して輸入 | 98万円 | 認証なしの直接取引 |
| | FLO認証生産者から1パレット輸入 | 115万円 | 発注者試算 65〜120万円の範囲内 |
| 砂糖 | 国内の一般砂糖 | 30万円 | 基準 |
| | FLO認証砂糖を直接輸入 | 45万円 | 調整金・手続きが上乗せされる前提 |
| | 国内のフェアトレード認証砂糖 | 52万円 | **実売価格**（25kg 13,000円 × 40袋） |

砂糖の国内調達を「輸入より高いが確実」ではなく **「輸入とほぼ変わらない」** 価格にしているのは、
発注者の調査どおり、日本の価格調整制度によって少量輸入の旨みが小さいためです。
授業では「なぜ輸入したほうが高くつくのか」を話題にできます。

## 2. 初期資金を 1,000万円 → 300万円 にした

いちばん高い組み合わせ（FLO認証カカオ115万＋FLO認証砂糖52万＋広告16.5万＋還元10万＝193.5万円）でも
1年目を実行できますが、余裕は大きくありません。「300万円で何を選ぶか」が最初の判断になります。

（`test/research.test.js` に、初期資金で最も高い選択が実行可能であることの検証を入れています）

## 3. バランスの再調整

1パレット制にすると **固定費（広告・還元）の重みが変わります**。

旧ルールは1ラウンド5ロット販売だったため、広告100万円は粗利550万円に対して18%でした。
1バッチにそのまま持ち込むと、広告が粗利の160%になり、薄利多売が成立しなくなります。
そこで固定費を粗利比で置き直しました。

| | 旧（5ロット） | 新（1バッチ） |
| --- | ---: | ---: |
| 広告（小 / 大） | 50万 / 100万 | 8万 / 16.5万 |
| 追加還元（中 / 大） | 30万 / 60万 | 5万 / 10万 |
| 安売りの需要増 | +85% | +60% |

安売りの需要増を +85% から +60% に下げたのは、1バッチ制では
「安くして数を売る」が強すぎたためです（`node tools/simulate.js` で確認）。

**結果: バランススコア 1,175 → 150。**
「どの戦略にも勝ち筋があり、支配的な戦略は見つかりませんでした」という判定に変わりました。

## 4. リサーチ加点（新設）

| 項目 | 加点 |
| --- | --- |
| ① フェアトレード認証生産者名が明確か | +10% |
| ② どれだけの生産者情報を取得したか | +10% |
| ③ フェアトレードプレミアムの事業がわかるか | +10% |
| ④ フェアトレードカカオ豆の値段 | 記録のみ |
| ⑤ フェアトレード砂糖の値段 | 記録のみ |

**加算ではなく総合得点への倍率（最大 ×1.3）** にしています。
加算にすると、経営が振るわなくてもリサーチだけで上位に入れてしまい、
「経営を考える」という教材の中心がぼやけるためです。
倍率なら、経営を頑張った会社ほど調べた成果が効きます。
（`test/research.test.js` に「リサーチ満点でも経営が伴わなければ勝てない」検証を入れています）

④⑤ に加点を付けていないのは、発注者の指定が①〜③にだけ
「あれば10％プラス」と書かれていたためです。④⑤ は点数ではなく、
**実際の発注に使う情報**として先生画面とCSVに出力します。

## 5. 数値を変えたくなったら

すべて `config/rules.mvp.json` の中にあります。変更後は必ず次を実行してください。

```bash
npm test                            # ルール検証 + 通しテスト
node tools/simulate.js --games 1000 # 支配的な戦略が出ていないか
node tools/tune.js                  # 良い数値の組み合わせを自動で探す
```
